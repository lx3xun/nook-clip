# 敏感凭据防护与本地加密

剪贴板是现代办公中最容易发生数据泄露的入口。很多时候我们随手复制的一段代码中，往往就夹杂着 OpenAI 密钥、云服务器 Token、测试数据库连接串或账号密码。

很多主流剪贴板管理工具会将历史记录以明文直接存储在本地 SQLite 数据库中，甚至后台悄悄联网上报，一旦设备遗失或遭遇恶意软件扫描，后果不堪设想。

NookClip 从底层架构开始就将**「本地隐私与数据主权」**放在第一优先级。

---

## 1. 自动敏感信息识别

NookClip 的底层 Rust 引擎内置了对常见敏感格式的高灵敏度模式探测：
- **API 密钥**：如 OpenAI（`sk-...`）、Anthropic、AWS 访问密钥、GitHub Token 等；
- **私钥与证书**：如 RSA Private Key、SSH 密钥块；
- **数据库连接**：形如 `postgres://user:password@host` 等包含密码口令的连接串；
- **个人隐私身份**：银行卡、身份证、手机号等结构化信息。

一旦检测到某条复制内容命中敏感规则，系统会立即为其打上敏感安全标记。

---

## 2. 本地 AES-256-GCM 硬件级强加密

对于标记为敏感的记录，NookClip 绝不以明文形式入库：

- **加密落盘**：数据在写入本地数据库文件前，必须经过工业标准的 **AES-256-GCM** 对称加密；
- **钥匙串联合守卫**：加密密钥由 macOS 系统的 **钥匙串（Keychain）** 与本地受保护文件双重保护。
- **防止物理拖库**：即便电脑遗失，他人把整个应用的数据文件夹拷贝到其他电脑上，打开数据库看到的也全都是无法破解的随机加密密文。

---

## 3. 防窥视遮罩（Masking）

在同事、朋友路过你的电脑屏幕，或者你在会议室投屏做演示时：

- **列表默认遮罩**：所有敏感记录在列表中会自动以 `••••••••` 圆点掩码显示，隐藏真实的密码与密钥字符串；
- **临时查看**：如果确实需要核对内容，可以用鼠标点击旁边的“眼睛”图标临时解密预览；
- **30 秒自动重锁**：查看后无需手动隐藏，30 秒无操作后，系统会自动重新锁上掩码，杜绝遗忘泄露。

---

## 4. 两条不可逾越的底线

为了保证绝对的安全合规，NookClip 在底层施加了两项硬性隔离：

1. **默认不上云**：所有被标记为敏感的记录默认严格留在当前设备本地，不上传 iCloud（仅当你主动开启「端到端加密」并显式授权同步敏感内容时，才会加密后跨设备同步）。
2. **不进检索**：敏感条目的明文内容**绝对不会写入 SQLite FTS5 全文搜索索引**，避免在索引文件中留下任何明文碎片。
