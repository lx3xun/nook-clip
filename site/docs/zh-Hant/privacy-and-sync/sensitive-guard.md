# 敏感憑證防護與本機加密

作為每天經手你所有複製內容的工具，剪貼簿裡不可避免會出現銀行卡密碼、SSH 私鑰、伺服器 Token 等核心機密。

NookClip 從底層儲存到介面展示，為敏感憑證設計了全鏈路的防護機制。

---

## 1. 自動辨識高風險敏感憑證

當你複製內容時，NookClip 的本機引擎會在毫秒內完成特徵檢測。一旦發現以下類型的內容，會自動為其打上 **「敏感憑證」** 標記（帶有小鎖圖示）：

- **主流雲端與 AI 金鑰**：OpenAI (`sk-...`)、Anthropic (`sk-ant-...`)、GitHub Token (`ghp_...` / `github_pat_...`)、AWS Access Key (`AKIA...`)、Slack Token 等；
- **非對稱加密私鑰**：`-----BEGIN PRIVATE KEY-----`、`BEGIN RSA PRIVATE KEY` 等 PEM 格式私鑰；
- **認證憑證**：JWT Token、Bearer Token、含帳密的資料庫連線字串（PostgreSQL / MySQL / MongoDB / Redis）；
- **個人金融與身分**：通過校驗演算法的銀行卡號、身分證號等。

---

## 2. AES-256-GCM 落盤加密

普通剪貼簿工具會把你複製的密碼以明文直接存進 SQLite 資料庫檔案裡，任何能讀取該檔案的第三方軟體都能一覽無遺。

在 NookClip 中：
- 所有被標記為敏感的記錄，在寫入磁碟前都會使用 **AES-256-GCM** 演算法進行高強度加密；
- 加密主金鑰受 macOS 系統級 **鑰匙圈（Keychain）** 與本機受保護檔案雙重守護；
- 磁碟資料庫中只存在密文，杜絕明文落盤洩漏。

---

## 3. 介面自動遮碼（防窺屏保護）

當你在辦公室、咖啡廳或者正在進行螢幕共享/錄影會議時，叫出剪貼簿很容易不小心把剛複製的密碼暴露給旁人。

- **列表與預覽預設遮碼**：敏感記錄在列表中會自動顯示為 `••••••••` 圓點遮罩，不會直接露出明文。
- **按需查看明文**：只有當你主動點擊預覽窗格上的 **「小眼睛（顯示明文）」** 按鈕時，才會臨時解密展示；一旦切換到其他條目或關閉面板，會立即重新恢復遮碼狀態。

---

## 4. 兩條不可逾越的底線

為了保證絕對的安全合規，NookClip 在底層施加了兩項硬性隔離：

1. **預設不上雲**：所有被標記為敏感的記錄預設嚴格留在當前裝置本機，不上傳 iCloud（僅當你主動開啟「端到端加密」並顯式授權同步敏感內容時，才會加密後跨裝置同步）。
2. **不進索引**：敏感條目的明文內容**絕對不會寫入 SQLite FTS5 全文搜尋索引**，避免在索引檔案中留下任何明文碎片。
